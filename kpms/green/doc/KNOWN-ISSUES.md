# Known limitations

This document describes the current standard-GumJS/KPM-shadow design. It is
not a compatibility claim for every Android kernel.

## Runtime

- The payload is Android ARM64/4-KB only. Stalker and non-Android backends are
  not part of this target.
- The Java bridge is a generated bundle from `vendor/frida-java-bridge`; ART
  internals are version-sensitive, especially hidden methods and fast JNI.
- Script evaluation is serialized through the agent control socket and result
  text is bounded by the fixed control response size.
- The Gum memory backend routes target writes and code patches through KPM.
  `mmap`/`mprotect` are still used for Gum-owned allocator pages and do not
  modify another module's code page.

## KPM shadow

- Every PATCH, RELEASE, and COUNT call must pass the exact token registered for
  that process mm. Tokens are generated by the root server and revoked on
  `exit_mmap` and module unload.
- A patch request is limited to one 4-KB page; the user-space backend splits
  larger writes at page boundaries.
- AArch64 block descriptors and contiguous PTE hints are split under a Green
  lock. The implementation still relies on the target kernel's private page
  table layout and does not have a portable `mmap_lock` ABI; validate against
  the exact KernelPatch/Android build before production use.
- Shadow page metadata is intentionally conservative on restore failure: the
  page remains tracked instead of freeing a page that could still be mapped.
- The same-page read-fault emulator supports only the instruction subset in
  `emu/`; unsupported instructions release the shadow page and let the normal
  fault path continue.
- Cache maintenance currently uses a system-wide instruction invalidate on
  supported ARM64 systems, which is correct but more expensive than a range
  invalidate.

## Operational checks

Load the KPM before starting `green`. If registration returns an error, the
server aborts the attach and prints “load green.kpm first”; it never falls
back to direct `memcpy`, `/proc/self/mem`, or a broker.
